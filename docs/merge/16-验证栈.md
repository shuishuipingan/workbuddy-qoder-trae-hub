### 判据套件明细




### 多标签页不互相覆盖（第 219 轮实测）

密钥表是"整表替换"。两个标签页同时开着时，后保存的会用**打开页面时**的快照覆盖。

**协议层复现（先证明 bug 存在）**：

```
B 新增 from-tab-B → ['国际','国内','合并通吃','from-tab-B']
A 用旧快照保存   → ['国际','国内','合并通吃']        ← B 的被静默删掉，两边都 200
```

**修复后（UI 端到端）**：A 在设置页里点「＋ 给 wb 新增」（此时 A 的页面还没有 B 那把 key）：

```
A 保存后 → ['国际','国内','合并通吃','from-tab-B','from-tab-A']
           B 的保留 ✓   A 的写入 ✓
```

规则：保存前先取现场，按 id 三方合并（别人新增的保留、本页编辑生效、点名删除优先）。

**合并 key 表同样会被覆盖（第 220 轮）**：

```
B 建 from-tab-B → ['from-tab-B']
A 用旧快照保存 → []                 ← 被清空，两次都 200
修复后（面板里新增）：['from-tab-B', 'from-tab-A']   ← B 保留 + A 写入
```

规则：保存前取现场；本页新增（id 为空）按名字去重追加；**删除必须显式给 id**
（否则无法区分"别人新增的"与"本页删掉的"）。




### 冷启动：空数据根却不空（第 224 轮）

用 `HUB_DATA_ROOT=.empty-data` 起一个"全新实例"，总览却显示：

```
今日错误率 67%（106/159） · 并集 59 个模型
```

查下去：门户把路由日志写死在 **<repo>/logs/route.jsonl**，没有跟随数据根 ——
于是每个实例都读同一份历史流量。

修法：`_route_log_path()` 优先 `paths.data_root()/logs/route.jsonl`，没设才退回仓库。
修后同一实例：`route-stats → {"total": 0, "today": {}}`，界面变成

```
没有合并 key（去设置里建一把） · 并集 59 个模型
开始使用 —— 还没有任何账号。三步就能跑起来
```

判据：`P15`（路径必须走 `_route_log_path` 且引用 `paths.data_root()`）+ `P15b` 反向对照。

### 设置开关不闪回（第 223 轮实测）

设置页的开关是"点了先变、再保存、保存完重拉"。这类交互最容易出现的 bug 是**闪回**：
点了变过去，重拉回来又跳回旧值，几百毫秒后再变——用户会以为没点上。

做法：每 120ms **重新查询**该开关（保存后 DOM 会被整体重建，抓节点引用会失效），记录 checked：

```
关 → 开:  000000 1111111111…    （约 845ms 处翻转，此后稳定）
开 → 关:  111111 0000000000…    （无回跳）
```

**两个方向都没有闪回。** 翻转点就是点击时刻；之后的重新渲染保持新值。

### 反复切换不累积（第 217 轮实测）

面板是**标签式**的：七个视图各自保留 DOM。这类结构最容易出两种泄漏 —— 定时器叠加、DOM 越切越多。

浏览器实测（合并档，三家引擎都有数据）：

| 观察项 | 结果 |
|---|---|
| 停在设置页 12 秒 | **0 个请求**（流水页的 5s 轮询确实停了） |
| 进出流水页 3 次后，停 12 秒 | 21 个请求 / 18 个日志请求 —— **与第 1 次完全相同，没有叠加** |
| 在已访问过的两页间往返 6 次 | DOM 节点 **3574 → 3574**，卡片 19 → 19 —— **零增长** |

> 首次访问某页时节点会涨（那是它自己的内容），之后不再增长。

### 演武：注册表里“加”第四家会发生什么（第 189 轮）

判据说“加一家引擎只需填一行 ENGINE_META”，这不能只写在文档里 —— 用临时探针实测：

| 判据/组件 | 加一家后 | 结论 |

| `aggregator.hub_usage` 键集合 | `merged, qd, trae, wb, **zz**` | ✅ 自动跟进 |

## 二、失败时先看哪

1. **看套件名**：`[FAIL]` 前面那个前缀就是归属（C=契约 / D=渲染 / V=视觉 / W=合并语义 / H=卫生 / S=引擎静态 / P=门户 / X=编排器自测 / M=变异）。

## 四·补 · 一条曾经"永远跳过"的断言（第 44 轮）

E12「端口归属」检查的是"这两个端口上的进程是不是我刚起的那个"——它守的是整仓最阴的一类假绿：
**端口被别人的实例占着，而 /health 照样 200**（别人回的）。

它在本轮的实测里被发现**从来没跑过**：

```
NameError: name 'subprocess' is not defined     ← 套件少写一行 import
  → except Exception: continue                   ← 被自己的宽 except 吞掉
  → 三个候选都"不可用" → 永远 SKIP
```

修法两条，缺一不可：
1. 补 `import subprocess`；
2. **把 `except Exception` 收窄成 `except (OSError, subprocess.SubprocessError)`** ——
   只有"这条 exe 起不来"才该继续试下一个，编程错误必须炸出来。

修后：该套件 19 检查(1 跳过) → **20 检查(0 跳过)**，E12/E12b 真的比对 OwningProcess 与 pid；
hub 全量也随之变成 `--strict` 全绿（此前那 1 条 SKIP 会被 strict 判红）。

> 教训与第 40 轮的 W44 同类：**"允许跳过"和"吞掉异常"是两件事**。
> 跳过要写清原因，异常要让它响。

### 同族清剿（第 45 轮）

按同一思路把 hub 侧的 9 处 `H.skip(` 与 11 处宽捕获过了一遍，又抓到一处同族风险：

`_test_portal.py` 探测 `--portal-port` 用的是 `except Exception: return False`。
后果：**`hub/server.py` 自己崩了（语法错/导入错）也会被当成"门户尚未落地" → 整个门户套件 SKIP → 一条红都不出。**

三层修法：
1. `except` 收窄到 `(OSError, SubprocessError)`；
2. **还看退出码** —— `proc.wait()` 对非零退出不抛异常，只靠 try/except 接不住"跑起来但崩了"；
3. 先分清 **"没有 server.py"（空树，应 SKIP）** 与 **"有 server.py 但 --help 跑不起来"（坏了，必须红）**。

> 第 3 条是元判据 **X03**（"门户缺失时应 SKIP")替我补的 —— 我第一版没做这个区分，
> 空树 fixture 立刻红，正好证明那条元判据在守门。

判据 **M8** 把这个护栏钉住：弄坏 `server.py`，门户套件必须报 `P01b` 红而不是跳过。

## 四·补三 · 两处"两份实现"的口径（都被判据钉住了）

### 1) 合并路由的四步顺序

前端 `chain.js` 的 `predictChain` 与后端 `router.candidates_for` 是**两份实现**，
以前只靠注释说一致。现在用行为断言钉住（**W51a–e**，另加变异 **M9** 证明它真会红）：

| 规则 | 期望 |
|---|---|
| 区域 | `prefer_realm` 先，另一区兜底（`prefer_realm=intl` 时 intl 段在前） |
| 引擎 auto | 就绪账号**多者先** |
| 引擎 auto 并列 | **wb 先**（后端源码里就是 `0 if e == "wb" else 1`） |
| `engine_prefer=wb/qd` | 该引擎永远在前，忽略就绪数 |

实测（`candidates_for`）：并列 (3,3) → `wb:cn, qd:cn, wb:intl, qd:intl`；
wb 多 (5,1) → wb 先；qd 多 (1,5) → qd 先；都为 0 → wb 先。

### 2) 模型清单的**两套语义**（都是故意的）

| 位置 | 语义 | 为什么 |
|---|---|---|
| `aggregator.hub_models`（面板） | 每引擎条目**原样并列** + 打 `engine` 标，**不去重** | 老板原话「把这俩里面支持的模型分开显示」 |
| `router.merged_model_list`（API） | 同名**合一条**，带 `engines` / `realm` 并集 | 客户端只关心"能不能调、在哪调" |

判据 **W52a/W52b** 分别钉住两条：谁把它们"顺手统一"，必有一边错——
要么面板丢引擎归属，要么 `/v1/models` 出现重复模型。

## 四·补六 · 时间范围（range）的口径

两个引擎都认 **day / week / month / all / custom**（wb 另收 today/1d、w、m 作为别名）。
传递给它们不认识的值**不会报错**，只会静默回落成全量 —— 所以面板的选项必须是上面这几个（判据 **W65**）。

`week` 是**日历周（周一起算）**，不是"最近 7 天"：

```
今天周一 → 本周起点 == 今天零点 → 「今天」与「本周」数字相同
```

> 我第一次对拍时正是周一，看到 week 与 day 完全一样，差点当成 bug 上报。
> 判断窗口是否生效，**别只看 week**：用 month 或 timeseries 的点数更稳（实测 day/week 5 点、month 6 点）。

## 四·补七 · 补丁管线（patches/）的两条只读自证

`docs/merge/patches/` 是 `sync_upstream.py` 的输入。补丁与目标树一旦错位，
管线会在**已经覆盖了一部分文件之后**才失败 —— 那时现场已经被改过。
所以把"错位"提前到只读检查里暴露（判据 **T04/T05**）：

|---|---|---|

## 五、已知边界（绿了也不代表这些没问题）

1. **英文界面仍会出现中文**：日志行、调度器摘要、"未找到可用账号"这类**原因串**都来自引擎，属数据不属文案（见 15 号文档）。
2. **空环境合并视图会退化**：没有账号时合并 key 没有可借用的上游凭据，`/v1/models` 会退成单边（`merged=false`），这是正确行为。
3. **引擎端口打开会 302 到控制台**：受控补丁（`# >>> hub-patch`），同步上游后需要照标记重贴；S10 判据会在丢失时立刻红。
4. **两个引擎的 usage 行结构不同**（第 75 轮实测）：wb 的行只有
   `at/iso/model/cost*/status/elapsed_ms…`，**没有 realm / account / engine**；
   qd 的行带 `realm/realm_reason/account/key_id` 等。后果：
   `/usage/recent?realm=cn` 对 **wb 是空操作**（照样返回全部），对 qd 才真的过滤。
   处置：面板只在**两端都有该字段**的地方用区域过滤；总览的「最近请求」已改为不传 realm。
5. **K 系列锚点依赖行号**：上游看板或 app.js 大改后锚点会漂，表现为"命中数从 1 变成 0"，改锚点而不是删判据。

## 条件渲染怎么测（第 120 轮补）

界面上有一大类东西是**"有数据才出现"**：账号「最近出错」徽标、模型「最近 24h 不可用」、
流水的归因标签、设置页的各种提示。这类东西最容易变成**没人见过、也没人守**的代码。

模板见 `admin/tests/_test_ui_states.js`。四条规则：

### 规则 1：每个条件都要**两个方向**

只测"有数据时出现"是不够的：把条件写成恒真，判据照样绿。
只测"无数据时不出现"更差：整块删掉也绿。

```
有数据 → 恰好 N 个标记        ← 正向
无数据 → 0 个标记             ← 反向
```

### 规则 2：不许拿整页文本当断言

实测踩过：判断"成功行没有归因标签"时写了 `!/上游/.test(整页文本)` —— 而
**筛选按钮本来就写着「上游」**。这条判据永远为真，等于没写。

要限定到**该在的那个容器**：

```js
// 行内标签在 tbody 的 .foot 里
const n = DOM.queryAll(root, 'tbody .foot').filter(匹配).length;
```

### 规则 3：直接 render 要补齐视图会话态

`render()` 假设 `self._ui` 已由 `load()` 初始化（筛选/排序状态）。
测试里直接调 render 会抛 `Cannot read properties of undefined (reading 'q')`：

```js
view._ui = { q: '', realm: 'all', cap: 'all', sort: 'name', dir: 'asc' };
```

### 规则 4：迷你 `t()` 桩返回的是 key，不是文案

这个套件里的 `ctx.t` 只是把 `{n}` 之类的占位符替换掉，**返回 key 本身**。
所以断言别去匹配中文，改成数元素 / 匹配 key：

```js
count(root, '.badge--warn') === 1 && /models\.recentlyUnavailable/.test(textOf(root))
```

### 想看成什么样？用夹具

判据只能告诉你"在不在"。要**看**它长什么样，用：

```bash
python hub/tools/make_fixture.py --out .fixture-data --scenario all
```

（注意 wb 的 `lastError` 是运行时字段，磁盘注入对它无效 —— 见 `18-数据契约.md` 第五节。）

## 怎么量"文字错位"（第 132 轮）

用户报的"字体错位"，静态判据看不出来 —— 必须**量**。做法（在真浏览器里跑）：

  && getComputedStyle(el).textOverflow !== 'ellipsis'

// ② 真实重叠：**逐行矩形**比较（getClientRects），不能用 getBoundingClientRect

⚠️ **按 display 分开取矩形**（第 59 轮修正）：

| 元素 | 取法 | 原因 |
|---|---|---|
| `inline` / `inline-block` | `Range.getClientRects()`（逐行） | 包围盒是所有行的**并集**，跨行时会误报重叠（实测 7 处假阳性） |
| `block` / `flex` / `grid` | `getBoundingClientRect()` | 反过来：对块级用逐行矩形，会把**子元素文本**算进来，又造出 20 处假阳性（第 59 轮实测） |

第 59 轮用这条规则复测「流水页 · 合并路由卡」的展开/收起两态：**0 裁切 · 0 重叠**。

实测结论（2026-10-19 · 500px 视口 · 7 个页签）：

| 页 | 静默截断 | 真实重叠 |
|---|---|---|
| 全部 7 页 | **0** | **1 处**（设置页 开关 × 说明文字，17px） |

那处已修：`.kv__v:has(> .switch)` 改成纵向排列（判据 **W92**）。

### 沙盒里量不了桌面宽度（实测限制）

本机沙盒的浏览器窗口被固定在 **500px**：
`Emulation.setDeviceMetricsOverride(1280×900)` 返回的 `innerWidth` 仍是 500，
`Browser.setWindowBounds` 报 `No web contents in the target`。
所以上面那张表**只覆盖移动断点**（<767px）。

要测桌面（≥1280）请在真浏览器里粘这段：

```js
(async () => {
  const views = ['overview','accounts','models','metrics','logs','api','settings'];
  for (const v of views) {
    location.hash = '#/' + v;
    await new Promise(r => setTimeout(r, 1200));
    const page = document.querySelector('.page[data-view="' + v + '"]');
    if (!page) { console.log(v, 'no page'); continue; }
    let clipped = 0, overlap = 0;
    const lineRects = (el) => {
      const out = [];
      const w = document.createTreeWalker(el, NodeFilter.SHOW_TEXT);
      while (w.nextNode()) {
        const t = w.currentNode;
        if (!t.nodeValue.trim()) continue;
        const rg = document.createRange(); rg.selectNodeContents(t);
        out.push(...rg.getClientRects());
      }
      return out.length ? out : [...el.getClientRects()];
    };
    const hit = (A, B) => A.some(a => B.some(b =>
      Math.min(a.right,b.right)-Math.max(a.left,b.left) > 2 &&
      Math.min(a.bottom,b.bottom)-Math.max(a.top,b.top) > 2));
    for (const el of page.querySelectorAll('*')) {
      const cs = getComputedStyle(el);
      if (!el.children.length && (el.textContent||'').trim()
          && el.scrollWidth - el.clientWidth > 2
          && (cs.overflow === 'hidden' || cs.overflow === 'clip')
          && cs.textOverflow !== 'ellipsis') clipped++;
      const kids = [...el.children].filter(k => (k.textContent||'').trim());
      for (let i = 0; i < kids.length; i++)
        for (let j = i + 1; j < kids.length; j++)
          if (hit(lineRects(kids[i]), lineRects(kids[j]))) overlap++;
    }
    console.log(v.padEnd(9), '截断', clipped, '重叠', overlap);
  }
})();
```

## 怎么造故障（第 38-39 轮实测）

验证"一家出问题时界面怎么说"，比正常态更重要。三种手法，按**侵入性从小到大**：

### 写盘原子性（第 236 轮）

扫全部持久化写点：43 处走 `tmp + json.dump`，配对 `os.replace` 20 次（多出来的是复用辅助函数）。
**三处是裸写**：

| 位置 | 内容 | 后果 |
|---|---|---|
| `wb_proxy.py save_persisted_realm` | 当前区域（intl/cn） | 写一半断电 → 下次启动读不出 → **悄悄退回默认区** |
| `qoder_agents.py _save_state` | **用户写的 agent 提示词** | 截断 → 整份状态解析失败 → **全空** |
| `trae_agents.py _save_state` | 同上 | 同上 |

三处都改成 `tmp + os.replace` —— 以**追加式 hub-patch 块**实现（不改上游行，
S04/S05 剥掉标记块后仍与上游逐字节相同）：

```python
# >>> hub-patch: atomic-state-write
def _save_state_atomic(...): ...
_save_state = _save_state_atomic
# <<< hub-patch: atomic-state-write
```

**破坏测试**：把 `qd/accounts/settings.json` 截断一半再启动 —— 面板 200、引擎 health ok，
解析失败退到默认值而不是崩溃（这是 fail-safe，可接受）。

判据：W116（三处必须 tmp+replace）+ W116b 反向对照。

### 写盘失败被说成"引擎不可达"（第 237 轮）

模拟磁盘写失败：在 tmp 路径上放一个**同名目录**（`settings.json.tmp`），让写入必然抛错。

**修复前**：

```
POST /api/wb/settings/save → 502
{"error":"cannot reach engine wb on 127.0.0.1:16711","kind":"engine_unreachable",
 "hint":"先起引擎：python -m hub.server ..."}
```

引擎**活着**（health 200），但异常从 handler 里逃出去 → 连接被关 → 客户端把"写失败"读成
"引擎不可达"，还给出**完全错误的处置建议**（去起引擎）。

**修复后**（三家各一段追加式补丁块 `settings-save-errors`）：

```
POST /api/wb/settings/save → 500
{"error":{"message":"settings not saved: [Errno 13] Permission denied: ...settings.json.tmp",
          "type":"write_failed"}}
```

顺带确认：**原文件没有被破坏**（内容与写入前逐字节相同）—— 原子写的 tmp 阶段失败不会动真文件。

#### 踩的坑（记下来）

- 三家的补丁块必须是**追加式**（不改上游行），否则 S04/S05 的"剥块后逐字节相同"立刻红；
- 剥块后**空行数量**也要与上游一致 —— 我前后改了三轮才对上（多一个空行也算差异）；
- 想加 S11 判据时发现该编号已被"客户端断开兜底"占用，新判据留待下轮换号（S12）。

#### 账号写入同样的暴露面（第 238 轮）

`do_POST` 里账号路由（`/accounts/*`）走 `self._handle_accounts(...)`，**在 try 块之外**
（那个 try 只覆盖 chat 路由）。也就是说：改启停 / 删除 / 导入时写盘失败，同样会关掉连接、
被读成"引擎不可达"。

三家各加一段 `account-write-errors` 兜底块（捕获 OSError/IOError/PermissionError →
500 `write_failed`）。

**已实测（第 239 轮）**：把目标账号文件本身换成同名目录，让 `os.replace` 失败：

```
POST /api/wb/accounts/set → 500
{"error":{"message":"account write not saved: [WinError 5] 拒绝访问...","type":"write_failed"}}
/api/wb/health → 200（引擎照常活着）
```

顺带记两个接口事实（本轮踩到的）：
* `/api/wb/accounts` 必须带 `?realm=cn|intl`，不带时返回空表；
* `/accounts/set` 的字段是 `uid`，不是 `id`。

### 写失败的可复跑验收（第 240 轮）

工具：`python hub/tools/verify_writefail.py`（自带临时数据根，起停一次真实实例）

实测输出：

```
[PASS] A  设置写失败 -> 500 write_failed
[PASS] A2 设置写失败后引擎仍活着
[PASS] B  账号写失败 -> 500 write_failed
[PASS] B2 账号写失败后引擎仍活着
[PASS] C  定价映射写失败 -> 500 write_failed
[PASS] C2 定价写失败后引擎仍活着
SUMMARY: 6 项，0 失败
```

造失败的办法（跨环境可复跑，不依赖 ACL）：
* 设置：`<settings>.json.tmp` 换成同名目录 → `open(tmp,'w')` 失败
* 账号：`<uid>.json` 换成同名目录 → `os.replace(tmp, path)` 失败

这两条与 `verify_persistence.py` 一起，构成"数据安全"这一块的发布前检查。

**定价映射是第三条（第 242 轮补）**：把 `pricing-overrides.json` 换成同名目录后，
`POST /api/wb/pricing/mapping` 原来同样表现为 `502 engine_unreachable`（"先起引擎"），
加 `pricing-write-errors` 补丁块后变成 `500 pricing mapping not saved: ...`，引擎仍 200。
注意：只有 wb 有这两个定价路由（qd/trae 没有该能力），所以补丁只落在 wb。

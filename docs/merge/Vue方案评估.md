## 三、两道真实的坎（都已过）

### 坎 1 · 主题桥接

本项目全站颜色走 tokens.css 的 **OKLCH 令牌**，主题靠 html[data-theme] 切换；
Element Plus 自带一整套 --el-* 变量。**不桥接 → 切主题时只有原生那部分变色，页面一半深一半浅。**

ep-bridge.css 的解法：**只写一次声明、只引用项目令牌、不写任何具体颜色** ——
令牌自己切主题时 EP 跟着切，**桥接层不需要知道有几种主题**。
弱化色（-light-3/5/7/8/9）用 color-mix **从当前主题实时算**，不是抄近似值。

实测：深浅两套主题下 --el-bg-color / --el-text-color-primary / --el-color-primary / 表格背景**全部跟随**。

### 坎 2 · in-DOM 模板的 HTML 解析规则

**症状**：搜索框在，三个按钮和两组单选**全没了，控制台一声不吭**。

```html
<!-- 错的 -->
<el-input v-model="q" clearable />
<!-- 对的 -->
<el-input v-model="q" clearable></el-input>
```

**根因**：in-DOM 模板（无构建、直接让浏览器解析 HTML）里 <el-input /> **不是自闭合的**。
HTML 解析器不认这个语法 → **把后面所有兄弟节点全吞成它的子节点** →
而 el-input 只渲染自己的 input → **后面的东西全消失且不报错**。

> ⚠️ **这条坑和「免构建」是绑在一起的** —— 用 SFC 的人永远遇不到（SFC 用真正的编译器）。
> **选了一条路，就要吃这条路的规矩。**

## 六、判据侧的处置（第 50 轮已完成）

把 vendor/ 放进 admin/ 后，**H2「无任何外链」当场红 16 处** ——
都是 element-plus.min.js 里 license 注释里的 lodash / openjsf 链接。

处置：EXCLUDE_DIRS 加 vendor，**并配一条补偿判据 H2c** ——
*页面里每个子资源都必须是本地相对路径，而且文件真实存在*。

**双向阳性对照**：

```
① 改成 CDN 引用     → H2c 红（报出确切 URL），**同时 H2 与 H4 也红** —— 三道守卫都抓到
② 指向不存在的文件   → H2c 红（文件不存在）
③ 还原             → 全绿
```

> **排除一个目录不等于开天窗** —— 关键是**那一条被削弱的东西，有没有别的东西接住**。

## 七、建议的铺开路径

**一次只动一页，随时能退回**：

1. 把桥接层 + 试验田结构搬成正式的「模型清单」页面

3. 手感与判据都过了，再逐页迁移

而这两类坑**第 7 轮和第 52 轮已经各踩过一次**，分开踩便宜得多。

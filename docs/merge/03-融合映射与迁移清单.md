## 4. 九大能力域深度映射

### 4.1 ★ 设备指纹（最高优先级）

| 项 | wb | qoder |
|---|---|---|
| 核心 | `wb_fingerprint.py:11-17` `derive_id(uid, salt)` → `md5(f"{salt}:{uid or 'anonymous'}").hexdigest()[:36]` | `qoder_fingerprint.py:20-33` **同算法同切片** |
| 盐串 | `"machine"`(:42) `"session"`(:43) `"req"`(:22) | `"machine"`(:245) `"session"`(:246) `"req"`(:38) `"machinetype"`(:45) |
| 桌面模板 | `wb_fingerprint.py:27-53` | `qoder_fingerprint.py:230-256` |
| 模块规模 | 53 行 | 256 行 |

**逐字段比对 `get_desktop_fingerprint` 实测**：两边 `releaseDate` 都是 `1789036585355`、`commit` 都是 `"5f9692923c93033111c51ad7b003eb80204a9b75"`、`osVersion` 都是 `"10.0.26220"`、`cpuCores` 都是 `20`、`memorySize` 都是 `24` —— **同一份模板的两个副本**。仅 `ideName` / `ideType` / `ideVersion` / `extName` / `extVersion` 不同（wb: WorkBuddy / 5.5.6 / workbuddy-desktop；qd: Qoder / 1.1.64 / qoder-desktop）。
**qoder 额外有**：`derive_machine_type`(:43) `derive_machine_token`(:48，SHA512+base64url[:43]) `vm_status`(:181) 本机虚拟化检测（`VM_BRANDS_CN`:63 / `_VM_DRIVER_FILES`:78 / `_local_vm_evidence`:118）。

**风险定量**：两引擎同库且账号 `uid` 相同时，`derive_id(uid,"machine")` 结果**完全相同**（同算法、同盐、同切片）⇒ 同一台"虚拟物理设备"同时给 workbuddy.ai 与 qoder.com 发请求。

**处置：重写为 `hub/core/fingerprint.py`，盐串加引擎前缀（01 号 §5 已定）**，并落实以下四条（第 2 条是对 01 号的必要细化）：

1. `hub/core/fingerprint.py` **必须同时提供** `derive_id(uid, salt, engine)` 与 `derive_id_legacy(uid, salt)`（旧算法逐字节冻结）。
2. **回退开关要按引擎分开**：01 号只给了一个全局 `WB_FINGERPRINT_LEGACY=1` —— 建议改为 **`WB_FINGERPRINT_LEGACY` / `QD_FINGERPRINT_LEGACY` 双开关**，否则灰度只能全量切、无法单侧回退。
3. **不要"顺手修正" `[:36]`**：`md5().hexdigest()` 恒 32 字符，`[:36]` 是恒等切片（`qoder_fingerprint.py:25-27` 已有原注释）。改成真 36 位 = 等价换盐。
4. 前缀格式用 01 号的 `hub:<engine>:<salt>`；注意它把 `uid` 放在 `salt` **之后**（`f"hub:{engine}:{salt}:{uid}"`），与旧算法 `f"{salt}:{uid}"` 的拼接顺序不同 —— **顺序也参与哈希**，这是必要的（否则前缀可被抵消），需在回退注释里写明。

**验收判据**：① `derive_id(uid,"machine","wb") != derive_id(uid,"machine","qd")`；② `derive_id_legacy(uid,"machine") == md5("machine:"+uid).hexdigest()[:36]`（与线上实现对拍）；③ 开 `*_LEGACY=1` 时输出与当前线上**逐字节相同**。

### 4.2 账号模型与导入链路

**模型**：见 §3.1。wb `class Account` 在 `wb_accounts.py:413`；qoder 在 `qoder_accounts.py:1132`。

**导入链路 —— 两套完全不同的信封，无共用面：**

| 环节 | wb | qoder |
|---|---|---|
| 桌面目录定位 | `desktop_auth_dirs`(:2649) `desktop_auth_dir`(:2673) `desktop_credential_candidates`(:2677) | `_localappdata`(:168) `_read_ini`(:173) `desktop_install_dir`(:192) |
| 扫描入口 | `scan_desktop_credentials`(:2689) | `scan_desktop_credentials`(:3363) |
| 密钥获取 | `desktop_atrest_key`(:2613) → `wb_atrest.hunt_key`(:669，**扫进程内存找明文密钥**) | `_read_chromium_os_crypt_key`(:3312，**Chromium os_crypt 主密钥**) |
| 解密 | `desktop_decrypt_tokens`(:2623) → `open_envelope`(:140) + `_gcm_open`(:283)（**AES-256-GCM + 自定义 framing**） | `qoder_sign.dpapi_unprotect`(:419) / `chromium_decrypt_v10`(:448)（**AES-128-CBC**） |
| CLI 凭据 | 无 | `_load_cli_user`(:3349)（`~/.qoder*/.auth/user`，AES-128-CBC） |
| 客户端目录缓存 | `read_product_config_models`（`wb_proxy.py:2821`） | `qmc_decrypt`(:345)（**QMC/HKDF+AES-256-GCM**） |
| 导出格式 | `EXPORT_FORMAT = "workbuddy-accounts"`(:2784) | `EXPORT_FORMAT = "qoder-accounts"`(:3544) |
| 导入归一 | `normalise_import_row`(:2876) + `VOLATILE_FIELDS`(:2790) + `RUNTIME_ONLY_FIELDS`(:2795) | `normalise_import_row`(:3609) |

**处置：两边各自保留，不做共用。** 理由：① 信封与密钥来源完全不同（GCM vs CBC；内存扫描 vs os_crypt/DPAPI）；② 抽公共层的收益是 0（无共同抽象），风险是 100%（改错一处 = 导入失败）。
**唯一值得共享的是「字段白名单」思路**：wb `VOLATILE_FIELDS`(:2790) / `RUNTIME_ONLY_FIELDS`(:2795) 明确「哪些字段不写回盘」——`wb_accounts.py:665-669` 有原注释说明它修的是「重启后复活旧的 429 标签」的 bug。**合并后 `engine` 也必须进白名单**，否则每个账号都会多写一次。

**验收判据**：① 两个 `scan_desktop_credentials` 各自返回结构不变（`file:line` 级对拍）；② 用真实桌面凭据各导入 1 次，落盘到 `data/accounts/{wb,qd}/`；③ 旧布局 `accounts/*.json` 可被 01 号 §3 的迁移逻辑识别并备份到 `data/legacy/`。

理由：① 两边都是「到点触发字符串任务」，qoder 侧设施（状态落盘、三类触发、补签判定、手动触发、状态查询）更完整 ⇒ **以 qoder 为骨架**；② 任务体本身就是引擎内部函数，用注册表隔离即可，不需要共享。
设计要点（硬约束）：

1. **任务表按引擎分区**：`TASKS = {"wb": [...], "qd": [...]}`，调度循环按 `engine` 取。
2. **状态文件分文件**：`data/scheduler/wb.json` / `data/scheduler/qd.json` —— 不可共用，否则 wb 的 01:00 夜猫会被 qoder 的 `_allow_complement_checkin`(:197) 误判。
3. **手动触发必须带 engine**：`trigger_now(engine, task)`，否则后台「立即执行」按钮会同时打两个引擎。
4. **保留 `_calc_next_fire`(:160) 的语义**：重启后不得重复触发已跑过的当日任务。

**验收判据**：① `data/scheduler/{wb,qd}.json` 各自内容与迁移前 `accounts/scheduler/state.json` 的对应子集一致；② 手动触发 wb 任务时 qoder 侧**零调用**（用 `add_log_entry` 计数断言）；③ 重启后不重复触发。

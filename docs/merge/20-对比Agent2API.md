# 对比 Agent2API：聚合层该怎么设计

> 参照项目：`<home>\Desktop\Agent2API-main`（Rust 网关 + Tauri 桌面壳，17 家 provider）。
> 本文只记「值得抄的」与「不能抄的」，不搬代码。

## 一、它怎么聚合的（读源码得出）

| 层 | 它的做法 | 文件 |
|---|---|---|
| 提供商 | **声明式配置**，不是代码：新增一家只加一份 provider 配置 | `core/custom_providers.rs`、`config/types.rs` |
| 模型命名 | **请求名 → 各家上游真名** 的映射表（`modelRules.mappings`），对外一套名字 | `core/routing.rs` 头部注释 |
| 选路 | **严格优先级**（同 provider 内 priority 唯一，小的先用）+ 按模型冷却排除 | `core/routing.rs` |
| 冷却键 | 用**上游真名**做 `rateLimits` 的键，不用对外别名 | `core/routing.rs`（这一条写了两千字解释） |
| 出口 | 每账号可绑独立代理，指纹按官方客户端伪装 | `core/proxy_pool.rs` |
| 面板会话 | access（2h，内存）+ refresh（30d，只存哈希、轮换、重放即整链作废）| `access.rs` |
| 报表 | SQLite 落库，请求量/成功率/token/缓存命中/365 天热力图 | `request_stats/` |
| 签到 | 每家一套策略的自动签到，开关+间隔在一页里 | `core/auto_checkin.rs` |

## 二、值得抄的四条

### 1. 模型别名映射（最要紧）

它把「客户端说的模型名」和「上游认的模型名」拆成两层。没有这层，同一个额度会被记在多个名字下。
它注释里那段实测很说明问题：同一账号上 `deepseek-v4.1-flash` / `gpt-5.6-luna` / `gpt-6-astra` 三个键的 resetAt 完全一样
（本就是同一份额度），账号页却显示成「3 个模型限流中」。

我们现在的做法是**按名字合并**（同名即同模型），跨引擎不做映射 —— 名字一致时没问题，不一致时会重复消耗/重复限流。

### 2. 冷却键用上游真名

别名请求撞限额后冷却写在别名上，真名请求读不到 → 照样选中这个账号，再撞一次。
这条对我们是「将来做映射时必须一起做」的：映射一旦引入，冷却/限流键就必须跟着改真名，否则第 1 条的好处会被抵消。

### 3. 会话双令牌（access + refresh 轮换）

我们是**单令牌且每次登录轮换**，代价很实在：换个浏览器登录，把上一个会话踢掉。我自己调试时被这条坑过好几次。
它的做法：短效 access 只放内存（重启即失效，浏览器凭 refresh 静默换新）+ refresh 只存哈希 + 重放检测。

### 4. 提供商是配置而不是代码

加第四家引擎时，我们是「写进 ENGINES 注册表 + 三个引擎各自的 patch 块」；它是「加一份 provider 配置」。
我们做不到完全声明式（三家引擎是 Python 进程、各有自己的协议 quirks），但**模型清单、能力位、映射表**可以搬家成配置。

## 三、不能抄的三条

| 它的做法 | 为什么不抄 |
|---|---|
| Rust + Tauri 桌面壳（~800KB Rust、单二进制） | 我们刻意保持 Python 标准库 + 浏览器面板：没有构建链，改完就能跑 |
| 每种语言一份 UI 文案（6 × 60–112KB 的 settings.js） | 我们是单张 messages 表，翻译只维护一处 |
| 会话 cookie 的「一枚装两段」等中转兼容补丁 | 那是桌面壳 + 宿主中转带来的复杂度，我们没有这层 |

## 四、落地顺序（按性价比）

| 优先 | 事项 | 状态 |
|---|---|---|
| P1 | 合并 Key 的作用域（模型 / 引擎 / 区域限制）| ✅ 本轮已做 |
| P2 | 面板会话双令牌（不再一登录就踢掉别的会话）| 待做 |
| P3 | 模型别名映射 + 冷却键跟随真名 | 待做（要动路由核心，先补测试）|
| P4 | 请求报表落库（热力图 / 成功率趋势）| 待做（现在是从引擎 usage 现算）|

## 五、P1 的具体做法（本轮）

合并 Key 条目增加两个可选字段：

```json
{ "name": "dsh", "key": "mrg-...", "models": ["deepseek-v4.1-flash"], "engines": ["wb"] }
```

- 空数组 / 不填 = 不限制（保持旧行为）
- `models` 非空时：请求的 model 不在列表里 → **403 + 明确原因**（而不是 401「无效 Key」）
- `engines` 非空时：候选引擎被裁到列表内；裁完为空 → 503 并说明「这把 Key 只允许 X 引擎」

为什么现在做这条：我们所有调用方（DSH、脚本、可能的第三方客户端）共用一把合并 Key，
一把泄露就是全量损失。加上作用域后，每把 Key 可以只开放它需要的那部分。

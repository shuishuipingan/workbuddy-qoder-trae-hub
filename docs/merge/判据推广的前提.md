# 判据推广的前提：**先确认两处的机制是同一种**（Lead 第 59 轮）

## 引子

第 58 轮我加了一条判据 `D21`：

> **同一个能力，筛选出来的条数 == 列表里带那个徽标的条数。**

它的好处是**不需要知道实现**就成立 —— 只要两处口径不一致就红。
带着它做过阳性对照（退回缺陷版 → 红，报出「筛出 3 / 徽标 1」），有效。

## 于是我想把它推广到「请求流水」页

那一页也有**同一对入口**：结果筛选（全部/成功/错误） vs 结果列的徽标。
写法照抄 D21 —— **结果它在桩里必然红：**

```
成功 筛出 28 条 / 带该徽标 22 条
错误 筛出 28 条 / 带该徽标 6 条      ← 两档筛出**同一个数**
```

「两档筛出同一个数」就是线索：**筛根本没生效**，我数到的是**未筛选的旧 DOM**。

## 根因：两页的「筛」不是同一种筛

| 页面 | 筛选机制 | 桩里能不能立刻见效 |
|---|---|---|
| **模型清单** · 能力筛选 | **客户端**：`repaint()`，同步重建表格 | ✅ 能 → D21 成立 |
| **请求流水** · 结果筛选 | **服务端**：`_reload()` → 异步 fetch → 重新渲染 | ❌ 不能 → D21b 必红 |

## 处置：撤掉它

**一条在自家环境里永远红的判据，比没有判据更糟：**

> 它会让「红」失去信息量。下次真出问题时，第一反应会是「哦又是那条」——
> **而判据的全部价值就在于「红了要去看」**。

所以在 `_test_dom_render.js` 里留了一段撤销记录，而不是悄悄删掉。

## 不变量本身仍然成立

浏览器实测（真环境，异步能等到）：

```
全部  50 行（全部「完成」）
成功  50 行  ✓ 与徽标一致
错误   0 行  ✓
```

**只是它需要异步等待，而 DOM 桩不具备这个能力。** 要守它得换环境（真浏览器驱动）。

## 结论：推广判据之前先问一句

> **这两处的「筛」是同一种筛吗？**

**同一个不变量，换个页面可能就不成立 —— 因为底层机制不同。**

这和之前那几条是同一族：

```
「能动画的」不是判据，「不触发布局的」才是
「跑绿了」不是证据，「退回缺陷版还绿吗」才是
「判据在这页成立」不代表「在别的页也成立」← 本轮新增
```

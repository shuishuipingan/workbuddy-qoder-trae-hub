# 14 · 合并档的「读写对称」

> 一句话：**读合并了，写也必须合并** —— 否则就是"看着是一份数据，动起来只有一半生效"。

## 一、这类 bug 长什么样

合并档（默认视图）的列表是**两个引擎拼起来的**：

* 账号池 = workbuddy 的 28 个 + qoder 的 4 个（每条带 engine 标）
* 请求流水 = 两边的行
* 福利中心 = 两张引擎卡

而 `api.post('/api/accounts/set')` 这种不带引擎前缀的写，会落到**默认引擎（wb）**。
于是：

| 操作 | 症状 |
|---|---|
| 对 qoder 账号点「停用 / 签到 / 删除」 | 请求带着 qd 的 uid 打到 wb → `no such account`（404）→ 界面「点了没反应」 |
| 点「Qoder 签到」卡 | 实际给 WorkBuddy 签了到 |
| 点「清空运行日志」 | 只清了 wb 的内存环形缓冲，qd 的还在 |
| 点「全部停用」 | 只停了 wb 那一半 |

**实测证据**（2026-10-19）：同一个 qd 账号 uid

```
POST /api/qd/accounts/set  → 200        ← 正确路由
POST /api/accounts/set     → 404        ← 修复前 UI 走的正是这条
```

## 二、三条修法

1. **行级动作按数据行的引擎走**
   `postTo(engineOf(row), 'accounts/set', …)` —— 引擎前缀 + 该引擎的面板令牌。
   账号池、福利中心的引擎卡都是这个模式。
2. **全局动作两边都做**
   `api.postBoth(path, body)` —— 清流水、批量启停、总览快捷动作（签到/领福利/巡检/刷积分）。
   结果按引擎汇总：`✓ WorkBuddy + Qoder · +12` / `✗ Qoder：原因`。
3. **只有一边有的动作要**说清**
   取价只有 wb 有定价层 → 按钮标注「仅 WorkBuddy」，不假装两边都做。

## 三、判据（admin/tests/_test_merged_writes.js）

| 项 | 钉住什么 |
|---|---|
| W1 | 账号 set / checkin / del 三条都走 `postTo(engineOf(a), …)` |
| W2 | 账号批量 `setAll` 在合并档走 `postBoth` |
| W3 | 运行日志清空在合并档走 `postBoth` |
| W4 | 总览四个双方动作走 `postBoth`，取价显式单引擎 |
| W5 | 福利中心读路径走聚合端点 `hub/rewards` |
| W7 | 福利中心 wb 卡打 wb、qd 卡打 qd |
| W6 | 阳性对照：把「裸 `post('set')`」样本喂给检测必须判红 |

> 都是**静态**判据（读源码），不做运行时桩 —— 运行时桩会把"实现细节"镜像成判据，
> 换实现就得改测试。这里要钉的是"有没有按引擎路由"这个**决定**。

## 三·补 · 读侧也在漏（本轮又抓到两处）

写侧修完后，按"所有 api.get 都扫一遍"又发现两处**读**只打默认引擎：

| 位置 | 症状 | 修法 |
|---|---|---|
| 数据指标 · 时序趋势 + 逐行明细 | KPI 八个数字已合并，但**图和明细还是 wb 一条线** | 合并档额外 `getBoth(timeseries/recent)`；时序按桶时间（`at`）相加、边界取并集；明细并集后按时间倒序 |
| 顶栏积分 | 「8.14 万」只是 wb 的，qd 的积分不在里面 | 合并档改走 `/api/hub/accounts`（聚合端点），`summarizeCredits` 直接吃 `items` |

判据：W8（时序+明细必须两边拉并合并）、W9（顶栏积分走聚合端点）。

合并算例（本机跑过）：wb `{at:1000, prompt:10}` + qd 无该桶 → 保留；
`{at:2000, prompt:20}` + `{at:2000, prompt:7}` → `27`；边界 lo=min / hi=max。

## 四、还剩什么没对称

* **导入类**（本轮修完，见下）：三个入口各有归属，**不能**一律打默认引擎。
  * `accounts/import/pat` —— **只有 qoder 有这条路由**（wb_proxy 里没有）。
    合并/qd 档定向到 qd；wb 档保持默认（404 = "该后端不支持"，这个提示本身是对的）。
    实测：`/api/qd/accounts/import/pat` → `400 PAT must start with pt-`（qd 在处理）；
    `/api/accounts/import/pat` → 401/404（路由根本不在 wb）。
  * `accounts/import`（JSON 文档）—— **按内容判引擎**：`format: "workbuddy-accounts"`
    或含 accessToken/refreshToken → wb；含 personalToken / campaignCodes / plan → qd。
    不判的话，字段碰巧兼容时会**静默进错的一边**（比报错更糟）。
  * `accounts/import/desktop` —— 合并档**并发扫两侧**，每条候选带 `_engine` 标，
    列表里显示引擎徽章，逐条导入按各自引擎走；"全部导入"走 `postBoth`。
    原来只扫默认引擎，qoder 桌面端的凭据根本扫不出来。
* 设置类写操作按"当前在管理哪个引擎"定向（设置页有引擎分段），这是**有意**的：
  两边的限额/定价/密码字段根本不是一套，硬合并会互相覆盖。

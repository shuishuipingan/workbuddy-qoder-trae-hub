# 06 · 后台视觉设计方向（v2 · 用户反馈「界面还是太难看了」）

> 决策人：Lead｜依据：`modern-frontend-design` 技能（已加载）+ 现状截图诊断 + 用户直接反馈
> **本文是后台外观的唯一权威**。改视觉前先读本文，改完按 §6 自检。

---

## 一、诊断：现在为什么"难看"

现状截图逐条看下来，问题不在"没样式"，在**没有视觉语言**：

| 症状 | 证据 |
|---|---|
| 一片惨白，没有层次 | 亮色主题下 `--bg` 与卡片背景几乎同色，卡片靠一条 1px 边线勉强分开 |
| KPI 是"标签+数字"平铺 | 数字没有视觉重量（字号小、无等宽、无对齐规则），4 张卡看起来像表格行 |
| 信息密度像草稿 | 行高松散、留白无节奏、键值对左右两栏没有对齐轴 |
| 没有"这是一个开发者工具"的气质 | 无等宽数字、无状态点语义色、无终端感、无玻璃层 |
| 动效缺席 | 切换视图是硬切，弹层直接出现，没有任何进入/离开过渡 |

**一句话：这是一份能跑的原型，不是一件产品。**

---

## 二、方向（定稿）

按技能里的品类表，本产品属于 **Developer tools + 数据密集控制台**，方向定为
**「Dark Technical Console」**——暗色优先的开发者控制台：

```
暗色底 + 极轻玻璃层 + 单一冷色强调 + 等宽数字 + 状态语义色 + 克制动效
```

**硬性取舍**：
- **暗色为默认**（`html[data-theme="dark"]`，缺省即暗），亮色作为完整可用的第二套。理由：控制台长时间盯盘、状态色在暗底上更醒目，也直接甩掉"白底草稿"观感。
- **不引入任何外部资源**：不放 CDN 字体、不引图标库、不加 JS 动效库。字体走系统栈，图标继续用内联 SVG / 单字符。
- **不用紫色渐变审美**，不做荧光办公室风。强调色只用一个冷色 + 一个青绿辅色。

## 三、令牌 v2（`tokens.css` 必须导出这些组）

```css
/* 画布与层次：四层而不是两层 —— 这是"有层次"的关键 */
--canvas      oklch(13% 0.015 265)      /* 页面底 */
--surface     oklch(17% 0.017 265)      /* 卡片 */
--surface-2   oklch(21% 0.018 265)      /* 卡内嵌块 / 表头 */
--overlay     oklch(24% 0.020 265)      /* 弹层 / 下拉 */

/* 文字三级 + 一级反白 */
--fg          oklch(96% 0.008 265)
--fg-dim      oklch(74% 0.012 265)
--fg-mute     oklch(56% 0.014 265)

/* 描边三级（越靠上层越亮一点，制造体积感） */
--line-faint  oklch(24% 0.014 265)
--line        oklch(30% 0.016 265)
--line-strong oklch(40% 0.018 265)

/* 强调：冷靛蓝 + 青绿辅色 */
--accent      oklch(68% 0.17 265)
--accent-2    oklch(72% 0.14 195)       /* 青绿，用于次级高亮/图表第二色 */
--accent-soft oklch(68% 0.17 265 / 0.14)

/* 语义（含 soft 底色，用于 pill） */
--ok --warn --err --info  + 各自的 --*-soft

/* 排版 */
--font-sans  系统栈（保持现状，不引外链）
--font-mono  ui-monospace, SFMono-Regular, "JetBrains Mono", Consolas, monospace
--fs-* / --lh-* / --track-tight(-0.02em 标题用)

/* 空间/圆角/阴影/动效/布局 沿用现有变量名，值调优 */
--r-xs..xl  --sp-1..8  --shadow-1..3  --dur-*  --ease-*
```

**规则**：组件里**零硬编码颜色**，一律走令牌；圆角一律 `--r-*`；动效时长一律 `--dur-*`。
暗色与亮色**都要独立通过 4.5:1 正文对比度**。

## 四、关键组件的目标形态（改动清单）

| 组件 | 现状 | 目标 |
|---|---|---|
| **顶栏** | 实色条 + 一排按钮 | 半透明玻璃（`backdrop-filter: blur(20px) saturate(180%)`）+ 极细底边；状态点带呼吸动画 |
| **侧栏** | 灰色文字列表 | 图标+文字，选中项**左侧 2px 强调条 + 轻微玻璃底**；分组标题小号大写；悬停有 120ms 位移 |
| **KPI 卡** | 标签小字 + 数字 | 数字用 `--font-mono` **大号等宽 + tabular-nums**，标签在上小号 dim；右上角放趋势/状态；卡片有 1px **顶部内高光**（inset highlight）制造体积 |
| **卡片** | 白底 + 边框 | `--surface` + `--line-faint` + `--shadow-1`；标题行与内容之间用一条 `--line-faint` 分隔 |
| **表格** | 普通表格 | 表头 `--surface-2` 小号大写 tracking；行悬停整行提亮；**数字列右对齐 + 等宽**；状态用 pill，不用纯文字 |
| **键值对** | 两列 | 左列 dim 固定宽、右列等宽数字；行间 1px faint 分隔 |
| **徽标/状态点** | 纯文字 | pill（soft 底 + 同色描边）；状态点用 `.dot` + 语义色，可加 1.4s 呼吸 |
| **空态 / 错误态** | 一行字 | 居中图标 + 标题 + 一句说明 + **一个动作按钮** |
| **弹层 / toast** | 直接出现 | `@starting-style` 进入（`opacity 0→1 + scale .96→1 + translateY 6→0`），遮罩带 blur |
| **图表** | 折线 | 面积渐变填充（`--accent` → transparent）+ 细网格线 + 圆点端点；空态走统一空态组件 |
| **骨架屏** | 灰条 | 微光扫过（现有 `hub-shimmer` 保留并调色） |

## 五、动效规范（克制，别炫技）

| 场景 | 做法 | 时长/曲线 |
|---|---|---|
| 视图切换 | View Transitions API（`@view-transition { navigation: auto }`），不支持则降级为淡入 | `--dur-slow` / `--ease-out` |
| 卡片/区块首屏进入 | `@starting-style` + 80ms 阶梯 | 300–400ms |
| 弹层/下拉/toast | `@starting-style`，位移 + 缩放 | 200–250ms / `--ease-spring` |
| 悬停（行、按钮、卡） | 只动 `transform` / `opacity` / `border-color` | 100–150ms |
| 数字变化 | 不做滚动动画，只保证等宽数字**不跳位** | — |

**硬约束**：只动 GPU 属性；每个动画都要有 `prefers-reduced-motion` 处理；视口内同时不超过 3 个动画。

## 六、验收（改完必须逐条自证）

1. **令牌合规**：`grep` 组件 CSS/JS 里**零硬编码颜色**（`#hex` / `rgb(` / `hsl(`），一律 OKLCH 令牌。
2. **双主题**：暗色与亮色各截图一张；**都能看清**、正文对比度 ≥ 4.5:1。
3. **零外链**：`<link>` / 外链 `@import` / 外链字体 / CDN 一律 0 命中（布丁的卫生判据会拦）。
4. **类名契约不破**：视图只用 `§10.1` 通用类；`bash admin/tests/run_all.py` 全绿。
5. **真浏览器截图**：6 个视图 × 2 主题 = 12 张，落到 `docs/merge/shots/`，并在报告里给出**改动前后对比**说明。
6. **不改行为**：所有 `data-*` 契约属性（`data-stat-value` / `data-view` / `data-label` / `data-row-key`）必须保留，否则视图的差异刷新会坏。

## 十一、附录 · JS 语法验收口径修正（第 4 轮 · 团子实测发现）

**问题**：`node --check <file>.js` 在**未声明 `"type": "module"` 的 `.js`** 上会走「脚本（CommonJS）解析路径」，
**对 ESM 语法错误误报通过**。团子给出的可复现对照（同一份字节流）：

| 检查方式 | 坏文件（末尾悬空语句） | 好文件 |
|---|---|---|
| `node --check bad.js` | **exit=0（误报通过）** | exit=0 |
| `node --check bad.mjs` | exit=1（抓到） | exit=0 |
| 真实 ESM import | **FAIL: Unexpected token ')'** | OK |

**这条坑在本项目已经踩过两次**：第 3 轮 `settings.js` 少一个右括号、第 4 轮 `metrics.js` 悬空语句，
两次**裸 `node --check` 都报通过**。教训是：知道一个坑不等于不再踩，**得把工具换掉**。

**新验收口径（硬性）**：任何 `admin/js/**/*.js` 的语法验收，必须至少满足一条 ——

```bash
# (a) 复制成 .mjs 再 check
cp admin/js/views/x.js /tmp/x.mjs && node --check /tmp/x.mjs

# (b) 真实 ESM 解析（决定性，推荐）
node -e "import('file:///C:/.../admin/js/views/x.js').then(()=>console.log('OK'),e=>{console.error(e.message);process.exit(1)})"
```

**裸 `node --check x.js` 不再被接受为验收证据。** 布丁请把这条并入判据。

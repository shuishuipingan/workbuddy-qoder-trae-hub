## 自动提醒 + 一键更新

代码在 `hub/core/updater.py`，面板入口在「设置 → 版本与更新」，顶部还有一条提醒条。

| 环节 | 行为 |
|---|---|
| 检查 | `GET /api/hub/update`，读 GitHub Releases 的 latest，和 `HUB_VERSION` 比；结果缓存 6 小时 |
| 提醒 | 面板加载时同一份缓存（queryKey `hub-update`）：有新版本就出黄条 + 「立即更新」 |
| 更新 | `POST /api/hub/update/apply`：下载 release zip → 覆盖代码；**数据路径写死跳过** |
| 重启 | `POST /api/hub/update/restart`：起一个脱离父进程的新实例，1.2 秒后旧进程退出 |

### 为什么"只覆盖代码"要写死

`updater.PROTECTED` 里列了永不覆盖的路径：

```
data/  logs/  state/  hub/settings.json  hub/route-settings.json
hub/engines/*/accounts/  hub/engines/*/usage/
```

更新是"用户点了按钮就自动跑"的动作，一旦覆盖到这些路径，等于把账号和用量清空。
所以这里不靠约定，靠代码里的白名单守卫。

### 重启为什么不用 execv

Windows 上 `os.execv` 会沿用同一个控制台与同一份监听，端口还没释放就 bind，必失败。
现在的做法是 `Popen(DETACHED_PROCESS)` 起新进程，再让旧进程延迟 1.2 秒退出 ——
新进程等待端口释放后接管，面板轮询 `/api/hub/health` 恢复即刷新。

## 发布流程（下次发版照做）

1. 改 `hub/__init__.py` 的 `HUB_VERSION`
2. `python hub/tools/release_check.py` 必须 GREEN
3. 同步发布副本：把 `hub/ admin/ docs/merge/` 等白名单路径复制到干净目录
4. `git commit` → `git tag vX.Y.Z` → `git push --tags`
5. GitHub 上建 Release（正文写变更）；`docker` workflow 会自动推 ghcr 镜像

> 更新功能只认 **Release**（不是 tag）：`updater.check()` 读的是 `/releases/latest`，
> 所以发版时记得建 Release，否则面板会一直显示"已是最新"。
